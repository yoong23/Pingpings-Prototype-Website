DATABASE (SQLite) - follows SRS Section 6.1
===========================================

Where is my data?
-----------------
In ONE file:  data/pingpings.db
SQLite is built into Node.js, so nothing extra has to be installed.
You need Node.js 22.13 or newer (check with:  node --version).

Tables (SRS 6.1)
----------------
users                    user_id, role_id, full_name, username, password_hash, account_status, created_at
products                 product_id, product_name, category, price, initial_stock, current_stock,
                         expiry_date, description, status, created_at
qr_codes                 qr_code_id, product_id, qr_code_data, created_at, status
stock_in                 stock_in_id, product_id, quantity, date, user_id, notes
stock_out                stock_out_id, product_id, quantity, date, user_id, notes
purchase_confirmations   confirmation_id, product_id, quantity, confirmation_status (YES/NO), user_id, confirmed_at
expiration_records       expiration_id, product_id, expiry_date, expiration_status, checked_at
activity_logs            log_id, user_id, action, entity_type, entity_id, created_at
roles                    role_id, role_name   (extra small table: users.role_id points to it)

Reports (SRS: "stores or generates") are generated by three SQL views:
report_inventory, report_stock_movements, report_expiration.

How the website fills the tables
--------------------------------
- Adding a product creates its row in products, its QR code in qr_codes
  (qr_code_data = the product code, e.g. PP-0001) and its expiration record.
- Stock-In  -> stock_in      Stock-Out -> stock_out
  The new stock level and the movement are saved together (all or nothing).
- QR scan: YES = a stock-out of 1 + a YES row in purchase_confirmations.
           NO  = nothing changes in stock + a NO row in purchase_confirmations.
- expiration_records are refreshed when products are saved and once every new day
  (good / near_expiry = 7 days or less / expired).
- activity_logs records: LOGIN, LOGOUT, PRODUCT_ADDED / UPDATED / REMOVED,
  STOCK_IN, STOCK_OUT, PURCHASE_CONFIRMED / DECLINED, USER_ADDED / UPDATED / REMOVED.
- "Deleting" a product or user marks it inactive (status / account_status) so the
  stock history and the logs keep pointing to the right record.

Security (SRS 5.2)
------------------
- Passwords are stored only as salted hashes (scrypt), never as plain text.
- Every request to the database needs a login (a token given by the server).
  Without logging in, nothing can be read or changed.
- Staff cannot manage users and cannot add, edit or delete products
  (they can record stock). The server enforces this, not just the screens.
- 5 wrong passwords in a row blocks that device for one minute.
- You stay logged in for 12 hours of use. Everyone has to log in again
  after the server is restarted.
- The data folder is never served to browsers.

Upgrading / first start
-----------------------
- Data from the previous SQLite version, or from an old data/db.json, is moved
  into the new tables automatically on the first start. Nothing is lost.
  A copy of the old database is kept in data/backups (before-upgrade-....db),
  and db.json is renamed to db.json.imported.
- Existing passwords keep working (they are converted to hashes).
- A brand-new install starts with: admin / admin123 and staff / staff123.
  Please change these passwords in User management.

Backups (SRS 5.3)
-----------------
- The server makes one automatic backup per day in data/backups
  (pingpings-YYYYMMDD-HHMMSS.db) and keeps the latest 14.
- To restore: stop the server (Ctrl+C), copy a backup file into the data folder,
  rename it to  pingpings.db  (replace the old one), then start the server again.
- Extra safety: copy the whole data folder to a USB drive now and then.

Looking inside the database (optional)
--------------------------------------
Open data/pingpings.db with the free app "DB Browser for SQLite"
(https://sqlitebrowser.org). Only look, do not edit, while the server is running.

Rules the database enforces
---------------------------
- Stock can never be below 0, quantities must be above 0, prices cannot be negative.
- Usernames (among active users) and product codes (among active products) are unique.
- A user role must be admin or staff; a confirmation must be YES or NO.
- At least one active Administrator must always exist.
If the website sends data that breaks a rule, nothing is saved and the website
shows "Could not save" with the reason.
